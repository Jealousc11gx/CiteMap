## 📌 TL;DR（执行摘要，3-5 行）
- **核心目标**：打造本地优先（local-first）、轻量、易用、高效的论文管理工具，定位为「本地 PDF / 已有 Zotero 库的增强层」，而非云端 SaaS、非 Zotero 正面替代。
- **关键决策**：MVP 聚焦「导入(M1) + 全文搜索(M3) + 数据可自取(M6)」这一获客最小可行组合；自动分类准确率 ≥85% 设为 release gate（低于此不上线）；付费点落在 Zotero 结构性做不到的本地 AI 分类 / 语义检索额度；M6「数据可自取」前置到 MVP 建立信任锚点。
- **下一步**：先验证两个闸门——2026 Q4 末 D1 激活率 ≥40%（产品是否成立）、2027 Q2 末付费转化 2%–4%（商业是否成立），再放大进阶阶段投入。

## 1. 产品目标

三个目标彼此正交：分别解决「进得来」「找得到」「拿得走」，各自独立可衡量，任一目标失败不能靠其他两个补偿。

### G1 — 零配置入库：让论文「进得来」，且整理成本低于整理收益

**问题映射**：P0 痛点「元数据脏 / 整理成本高于收益 → 用户直接放弃整理」。

**目标陈述**：用户从「拖入一堆 PDF」到「拥有一个元数据正确、已自动归类的可用文献库」，无需任何前置配置、无需学习概念模型、无需逐条手工修补。

**成功指标**：

| 指标 | 目标值 | 口径 |
|---|---|---|
| 首次导入激活率（D1） | ≥ 40% | 新用户首日完成「导入 ≥ 50 篇 PDF 且完成一次自动分类」的比例 |
| 元数据自动解析准确率 | ≥ 90%（标题/年份），≥ 85%（作者列表完全正确） | 抽样 500 篇混合来源 PDF 人工核对 |
| 自动分类准确率 | ≥ 85%（**低于此门槛不上线**） | 标注集上 top-1 建议标签与人工标注一致率 |
| 首次入库耗时 | 500 篇 PDF ≤ 10 分钟（含解析+分类），全程无需人工干预 | M1 Pro / 16GB 基准机 |
| 上手时间 | 从安装到看到第一批已分类结果 ≤ 5 分钟 | 无引导可用性测试中位数 |

### G2 — 记忆式检索：让论文「找得到」，用模糊记忆也能命中

**问题映射**：P1 痛点「靠模糊记忆找不到论文，需要全文 + 批注一起检索」。

**目标陈述**：用户以任何残缺线索（半句话、一个概念、自己当时写的一句吐槽笔记、某张图的描述）发起检索，都能在一次搜索内定位到具体论文的具体页。

**成功指标**：

| 指标 | 目标值 | 口径 |
|---|---|---|
| 全文检索响应时间 | < 300ms（P95）@ 10,000 条目库 | 关键词检索，冷启动后 |
| 语义检索响应时间 | < 1.5s（P95）@ 10,000 条目库 | 本地向量检索 |
| 检索成功率 | ≥ 80% | 用户发起检索后 60s 内打开某篇论文的会话占比 |
| 批注命中占比 | ≥ 15% | 检索结果被点击项中，命中来源为「笔记/高亮」的比例（验证批注入检索的价值） |
| 检索零结果率 | ≤ 10% | 非空查询返回 0 条的比例 |

### G3 — 数据主权：让数据「拿得走」，且随时可验证

**问题映射**：P2 痛点「同步冲突 / 厂商锁定 / 数据丢失焦虑」；同时对应市场侧「合规 + local-first 回潮」机会。

**目标陈述**：用户的文献库在任何时刻都是一份人类可读、工具无关的本地资产（SQLite + 明文目录结构 + 原始 PDF）；卸载本产品不损失任何数据；AI 处理默认不出本机。

**成功指标**：

| 指标 | 目标值 | 口径 |
|---|---|---|
| 数据可自取验证 | 100% | 关闭应用后，仅用文件管理器 + 任意 SQLite 客户端即可取回全部 PDF、元数据、笔记、高亮 |
| 一键导出完整性 | 100% 无损往返 | 导出为 BibTeX + PDF 目录 + Markdown 笔记，再导入 Zotero 校验字段无丢失 |
| 默认离网 | 100% | 默认配置下应用无任何出站网络请求（元数据在线补全需用户显式授权，且逐次可见） |
| 备份恢复成功率 | ≥ 99.9% | 自动备份 → 灾难恢复演练通过率 |
| 同步冲突数据丢失 | 0 | 任何冲突场景下双版本均保留，用户显式二选一 |

**目标正交性说明**：G1 关注「输入侧成本」，G2 关注「使用侧效率」，G3 关注「退出侧信任」。不设置「用户量」「收入」类目标于此层，避免功能决策被增长指标污染。

## 2. 用户故事

### US-1｜博士生批量脱困（Persona A · 小林）

> 作为一名 **计算机方向三年级博士生**，我的 `~/Downloads` 和 `~/papers` 里堆着 **1,400 篇** 命名混乱的 PDF（`1706.03762.pdf`、`最终版-2.pdf`、`sci-hub-xxx.pdf`），
> 我希望 **把整个文件夹拖进来后自动完成解析、去重、打标签**，
> 以便 **我不用再花两个周末做整理，就能直接开始写文献综述**。

**关键约束**：不能要求我先建好文件夹体系；解析不出来的必须明确告诉我是哪几篇，而不是悄悄填个错年份。

**触达模块**：M1（批量导入/去重/解析失败标红）、M2（自动打标签）、M5（LaTeX 直连）

---

### US-2｜PI 的项目视图与零错误导出（Persona B · 张教授）

> 作为一名 **管理 5,000+ 篇文献、同时推进 4 个课题的 PI**，
> 我希望 **按「项目」把文献分组，并在投稿前一键导出该项目的参考文献，且保证每一条都绝对正确**，
> 以便 **我不必在提交截止前一晚逐条核对 BibTeX，也不必担心引用错年份被审稿人抓住**。

**关键约束**：库到 5,000+ 条时搜索不能变慢；citekey 一旦生成永不漂移；导出前必须有一个「问题条目清单」告诉我哪些字段缺失或可疑。

**触达模块**：M2（项目分组）、M3（大库性能）、M5（citekey 稳定 + 导出前校验）、M6（备份）

---

### US-3｜跨学科研究者的多维标签（Persona C · Maya）

> 作为一名 **横跨认知科学、HCI 与公共政策的研究者**，我的文献来源极其异构（期刊 PDF、arXiv、政府白皮书、会议 slides、网页存档），
> 我希望 **给一篇论文同时打上「方法：眼动」「领域：HCI」「用途：开题引用」等多个维度的标签，并能自定义我自己的元数据字段**，
> 以便 **同一篇论文能在不同课题的检索路径里都被找到，而不是被锁死在一个文件夹里**。

**关键约束**：标签必须是一等公民、文件夹只是辅助；智能分类规则要能预览影响范围再决定是否执行；非标准来源（无 DOI）也要能被妥善收录。

**触达模块**：M1（异构来源）、M2（多标签 + 自定义字段 + 规则预览）、M3（多维筛选）

---

### US-4｜写作时的「我记得有一篇……」（Persona A/B/C 共同）

> 作为一名 **正在写 Related Work 的研究者**，我只记得 **「有篇论文里提到过某种对比实验设置，我当时还在页边写了句『这个 baseline 不公平』」**，
> 我希望 **搜索这句我自己的笔记或那段模糊的概念描述，就能直接跳到那篇 PDF 的那一页**，
> 以便 **不打断写作心流，30 秒内把引用补上**。

**关键约束**：检索必须同时覆盖标题/摘要/正文/我的笔记与高亮；结果要显示命中上下文片段；点击直达 PDF 对应页并高亮命中处。

**触达模块**：M3（全文 + 批注检索、上下文跳转）、M4（阅读器定位）

---

### US-5｜审稿人的合规红线（Persona B / 新增高价值场景）

> 作为一名 **正在评审 3 篇未发表稿件的审稿人**，出版商明确禁止我把稿件上传到任何第三方服务，
> 我希望 **在完全离线的状态下，仍然能用 AI 帮我分类、做语义检索、导出批注笔记**，
> 以便 **既提高评审效率，又不违反保密协议**。

**关键约束**：必须能一眼确认「此刻没有任何数据出本机」；需要一个可截图、可向机构证明的「离线模式」状态标识。

**触达模块**：M6（本地优先 + 离线模式开关）、M2/M3（本地 AI）、M4（批注导出）

## 3. 用户研究洞察（整合瑞思结论）

### 3.1 三大核心痛点

| 编号 | 痛点 | 表现 | 根因 | 产品应对 |
|---|---|---|---|---|
| **P0** | 元数据脏 / 整理成本 > 整理收益 → **直接放弃整理** | 库沦为「PDF 垃圾场」；文件名即全部信息；重复文件多份 | 现有工具要求用户先建体系再入库；解析失败静默填错，用户逐渐不信任自动化 | M1 零配置批量导入 + 高准确率解析 + **解析失败显式标红** + 自动去重；M2 导入即自动打标签 |
| **P1** | 靠模糊记忆找不到论文 | 记得内容记不得标题；记得自己写过的批注但搜不到；只能靠肉眼翻列表 | 主流工具检索只覆盖标题/摘要元数据；批注笔记游离在检索之外；无语义检索 | M3 正文全文检索 + **批注笔记纳入同一检索索引** + 语义检索 + 命中上下文跳页 |
| **P2** | 同步冲突 / 厂商锁定 / 数据丢失焦虑 | 云同步冲突后不知道保留了哪份；担心厂商涨价或停服；不敢把唯一副本交给工具 | 云优先架构把数据格式私有化；冲突处理黑箱 | M6 明文可读库结构（SQLite + PDF 目录）+ 云同步可选 + WebDAV + **冲突可视化二选一** + 一键完整导出 |

**优先级判断**：P0 决定「用不用起来」，P1 决定「用不用得爽」，P2 决定「敢不敢把身家托付」。三者不可互替。

### 3.2 三类 Persona

| 维度 | **A · 博士生小林** | **B · 资深 PI 张教授** | **C · 跨学科研究者 Maya** |
|---|---|---|---|
| 库规模 | 800 – 2,000 篇 | 5,000+ 篇 | 1,000 – 3,000 篇，来源极异构 |
| 核心诉求 | 批量导入、快速脱困、LaTeX 直连 | 稳定可检索、按项目分组、导出绝对正确 | 多标签而非单文件夹、自定义元数据 |
| 容忍度 | 容忍 beta，愿意试新工具 | **对数据错误零容忍**，不愿迁移 | 容忍复杂配置，但拒绝僵化结构 |
| 付费意愿 | 中（价格敏感，但痛感最强） | 高（时间成本极高，机构可报销） | 中高 |
| 采纳角色 | **最高价值早期用户 / 传播源** | 决策者 / 机构采购影响者 | 差异化功能的需求驱动者 |
| 关键失败点 | 导入慢或解析烂 → 当天卸载 | 出现一次错误引用 → 永久流失 | 强制单文件夹归属 → 判定「不适合我」 |

### 3.3 关键诉求清单（直接转化为需求约束）

| # | 诉求 | 转化为的硬性约束 |
|---|---|---|
| R1 | 解析失败 **显式标红**，而非静默填错 | 任何低置信度字段必须带视觉标记 + 「待确认」队列，禁止用猜测值静默落库 |
| R2 | **标签为主、文件夹为辅** | 数据模型中标签为多对多一等公民；文件夹为可选的单一归属视图，非必填 |
| R3 | 智能分类规则 **可预览、可撤销** | 规则执行前必须展示「将影响 N 篇，示例 10 篇」；执行后生成可一键回滚的操作批次 |
| R4 | **批注/笔记必须纳入检索** | 笔记与高亮进入与正文同一份检索索引，检索结果标注来源类型 |
| R5 | 高亮/笔记 **导出 Markdown 并保留页码回链** | 导出格式含 `[p.42](citemap://open?id=xxx&page=42)` 形式的可点击回链 |
| R6 | 默认 **本地优先、明文可读库结构** | SQLite（非加密、schema 公开文档化）+ 原始 PDF 按可读路径存放 |
| R7 | 云同步 **可选**、支持 **WebDAV** | 同步为 opt-in；不绑定自有云；支持用户自带网盘 |
| R8 | 同步冲突 **可视化二选一** | 冲突时并排 diff，用户显式选择，双版本均不删除 |

### 3.4 研究给出的优先级建议

- **M1 + M3 = 获客最小可行组合**（能进来、能找到，即构成独立价值）
- **M6「数据可自取」= 转化说服点**（打消 P2 焦虑，是付费前的信任前提）
- **M4 批注导出 = 留存点**（笔记沉淀越多，迁移成本越高，形成正向锁定）
- **M2 高级智能规则可后置**（基础自动打标签必须在 MVP，复杂规则引擎可迭代）

### 4.2 结论：全场无一款同时满足「本地优先 + 轻量 + 智能」

- **本地优先阵营**（Zotero / JabRef / Obsidian 组合）：数据主权好，但**重**（Zotero 概念负担 + 插件拼装）或**极客**（JabRef 面向 BibTeX 熟手），且**完全没有 AI 能力**。
- **智能阵营**（SciSpace / ReadCube / Mendeley AI）：AI 能力强，但**全部云端且必须上传全文**——对审稿人、未发表稿件处理者、受 GDPR/FERPA 约束的机构构成**硬性合规阻断**。

两个阵营之间存在一条清晰的、无人占据的对角线。

### 4.3 三个差异化空白（我们的进攻方向）

| # | 空白 | 现状 | 我们的主张 | 对应模块 |
|---|---|---|---|---|
| **空白①** | **本地 AI 自动分类** | 全场空白：语义打标 / 主题聚类 / 归档建议，无一款本地实现 | 端侧小模型完成语义打标与主题聚类，导入即分类，准确率 ≥85% | M2（+M1） |
| **空白②** | **本地语义搜索 + 数据主权** | 语义检索只有云端方案，且必须上传全文 | 本地嵌入 + 本地向量索引，语义检索全程离网 | M3 |
| **空白③** | **零配置轻量层** | 本地阵营上手成本普遍 30 分钟起 | 5 分钟上手；拖入即完成「入库 → 抓元数据 → 归类」一步到位 | M1（+M2） |

### 4.4 Battle Card：vs Zotero（主要参照物）

| 我们赢在 | Zotero 赢在 |
|---|---|
| 上手快（5 分钟 vs 概念学习曲线） | **18 年生态**：100+ 抓取器、7,000+ CSL 样式、Better BibTeX |

**打法**：**不拼引文生态**。引用层完全采用标准 **BibTeX / CSL**，与 Zotero、LaTeX 无损互操作；**定位为 Zotero 的互补层 / 上游**——用户可以「用我们导入与检索，用 Zotero 出引文」，迁移无痛、共存无冲突。

**最大风险**：Zotero 免费 → 整体赛道**付费意愿低**。

- **P0**：MVP 必须交付，缺任一条则产品不成立，不可上线

### 6.1 M1 · 论文导入与元数据提取

## 8. Non-goals（明确不做）

以下内容在 v1（含 MVP 与首个正式版）**明确不做**。列出理由，避免反复讨论。

| # | 不做什么 | 理由 |
|---|---|---|
| **NG-1** | **不做群组协作 / 共享库** | Zotero 群组库是其成熟能力，正面竞争无胜算；协作会引入服务端状态，直接违背 local-first 与 G3 数据主权。 |
| **NG-2** | **不做云端 SaaS / 不做「云优先」架构** | 云优先是 Mendeley 引发 power user 反弹的根因；我们的全部差异化建立在「数据不出本机」之上。同步是**可选附加**，不是产品形态。 |
| **NG-3** | **不内置大模型训练 / 不做模型微调能力** | 本地 AI 的价值在「推理不出本机」，不在「让用户训模型」。训练能力会把轻量工具变成重型平台，违背差异化空白③。 |
| **NG-4** | **不将用户文献数据用于任何模型训练** | 合规楔子（D3）的前提。此条为**不可协商的产品承诺**，需写入隐私政策与首启说明。 |
| **NG-5** | **不做 Word / Google Docs 引文插件** | 竞析结论：不拼引文生态。引用层走标准 BibTeX/CSL，用户可继续用 Zotero 的 Word 插件——我们做上游，不做替代。 |
| **NG-6** | **不做通用网页抓取器生态（100+ translator）** | Zotero 18 年积累不可短期追赶。仅覆盖 ≤10 个核心学术源（P2），其余场景引导用户走 Zotero 导入。 |
| **NG-7** | **不做自研 CSL 引文样式库** | 直接复用社区标准 CSL 生态，零成本获得 7,000+ 样式。自研毫无收益。 |
| **NG-8** | **不做移动端 App（iOS/Android）** | 本地库 + 大文件 + 本地 AI 推理在移动端约束下体验必然劣化；v1 聚焦桌面。移动端最多考虑「只读查看」，且不在 v1 范围。 |
| **NG-9** | **不做文献综述自动生成 / AI 写作** | 属于 SciSpace 类产品赛道，与「管理与检索」的产品定位正交，且学术伦理风险高。 |
| **NG-10** | **不做机构级管理后台 / SSO / 席位管理** | 机构市场占 57–68%，但需要完整的销售与合规体系。v1 走个人开发者路线，机构化列入长期评估，不占用当前资源。 |
| **NG-11** | **不做全文 OCR（扫描版 PDF 文字识别）** | 高成本、低频（多数现代论文含文本层）。对无文本层 PDF 明确提示「不可全文检索」，不静默失败。 |
| **NG-12** | **不做 PDF 编辑（页面增删、表单填写、签名）** | 阅读器只服务「读与批注」，不做 PDF 工具。 |

**范围管理规则**：本 PRD 生效后，**每新增一条 scope，必须同时移除一条等价工作量的 scope，或明确延长时间线**。好想法但不在当前范围内的，进入「停车场」（见 §10 附录）而非直接塞入需求池。

## 9. 时间线 & 里程碑

> 高层面三阶段划分。**具体季度排期、人力分配与依赖关系由路线图交付物给出，本节不做详细排期。**

### 阶段一：MVP —「能进来、能找到、能带走」

**目标**：验证 G1 + G2 + G3 的最小闭环，跑通激活定义（导入 ≥50 篇 + 完成一次自动分类）。

| 项 | 内容 |
|---|---|
| **覆盖模块** | **M1（核心）+ M2（基础）+ M3（关键词）+ M5（导出正确性）+ M6（本地）** |
| **交付需求** | 全部 18 条 P0（约 154d） |
| **不含** | M4 全部、语义检索、云同步、规则引擎 |
| **发布门槛（Release Gate，全部满足才可上线）** | ① 自动分类 top-1 准确率 **≥ 85%**（不达标不上线）；② 10k 条目全文检索 P95 **< 300ms**；③ 元数据标题/年份准确率 **≥ 90%**；④ 数据可自取实机演示通过（卸载后仍可取回全部数据）；⑤ 默认配置抓包验证零出站请求；⑥ 5,000 条 Zotero 库导入 100% 条目一致 |
| **验证指标** | **D1 激活率 ≥ 40%**；首次 500 篇导入 ≤ 10 分钟；无引导上手 ≤ 5 分钟 |
| **主要风险** | 元数据解析准确率不达标（缓解：先做「标红」再做「提准」，保证不出错优先于全覆盖） |

### 阶段二：迭代 —「留得住、信得过」

**目标**：补齐留存杠杆（批注沉淀）与信任杠杆（可选同步），完成免费 → 付费的价值分层铺设。

| 项 | 内容 |
|---|---|
| **覆盖模块** | **M4（全部）+ M3（语义检索）+ M2（规则引擎/项目视图）+ M6（WebDAV/网盘/冲突）+ M1（版本识别/监听文件夹）+ M5（LaTeX 监听）** |
| **交付需求** | 全部 16 条 P1（约 136d） |
| **关键交付** | 本地语义检索（差异化空白②）、批注 Markdown 导出含页码回链（留存点）、同步冲突可视化二选一（P2 焦虑终结） |
| **发布门槛** | ① 语义检索 top-5 相关率 **≥ 70%**，P95 **< 1.5s**；② 同步冲突场景**数据丢失 = 0**；③ 备份恢复成功率 **≥ 99.9%**；④ 批注导出 Markdown 可被 Obsidian 直接识别 |
| **验证指标** | 4 周留存 ≥ 35%；检索结果中批注命中占比 ≥ 15%；免费 → 付费转化进入 **2%–4%** 建模区间 |
| **主要风险** | 语义检索本地资源占用过高（缓解：索引构建可后台/可关闭，提供轻量与完整两档模型） |

### 阶段三：进阶 —「守得住、扩得开」

**目标**：加固付费护城河（Zotero 结构性做不到的四项），并向合规敏感人群做定向扩张。

| 项 | 内容 |
|---|---|
| **覆盖模块** | **M2（主题聚类/智能收藏夹）+ M3（相似推荐/排序）+ M4（分屏/阅读状态）+ M5（CSL 样式）+ M6（端到端加密同步）+ M1（网页抓取/自定义字段）** |
| **交付需求** | 全部 12 条 P2（约 85d） |
| **关键交付** | 端到端加密同步（付费点四）、主题聚类归档建议、核心源网页抓取 |
| **验证指标** | 大库（10k+）用户占比与其付费率显著高于均值（验证「大库性能」付费假设）；审稿人/未发表稿件人群的获客成本显著低于均值（验证 D3 定位假设） |
| **主要风险** | 付费意愿仍不足（缓解：阶段二末必须完成付费点验证，若 2% 下限未达成，阶段三优先做定价与打包实验而非继续加功能） |

## 10. 待确认问题

以下问题需**产品负责人拍板**或需通过实验验证，PRD 无法单方面决定。

### 10.1 需要决策的开放问题

| # | 问题 | 背景与影响 | 需要谁拍板 |
|---|---|---|---|
| **Q1** | **本地 AI 模型的体积与硬件下限如何取舍？** | 分类准确率 ≥85% 与「轻量」定位存在张力。若需 2GB+ 模型，安装包与内存占用将冲击「5 分钟上手」体验；若压到 300MB，准确率能否守住 85% 门槛存疑。是否接受「基础模型内置 + 增强模型可选下载」的双档方案？最低支持配置是 8GB 还是 16GB 内存？ | 产品负责人 + 技术负责人 |
| **Q2** | **85% 分类准确率门槛的测量口径由谁定义？** | 「准确率」高度依赖标注集构成（学科分布、标签粒度、单标签 vs 多标签）。必须在开发启动前冻结一份公开的基准标注集与评测脚本，否则该 release gate 无法执行。基准集规模、学科覆盖、由谁标注？ | 产品负责人 + 数据分析 |
| **Q3** | **MVP 是否真的可以完全不含 M4（阅读与批注）？** | 本 PRD 将 M4 整体置于 P1。但 REQ-M3-02（批注纳入检索）是 P0——若无阅读器，用户在 MVP 阶段无从产生批注，该 P0 能力在 MVP 期实际处于空转。可选方案：MVP 纳入一个极简只读阅读器 + 高亮（约 +18d），或接受 M3-02 在 MVP 期仅覆盖导入的既有批注。 | 产品负责人 |
| **Q4** | **免费档与付费档的分界线具体划在哪里？** | 决策 D4 指明付费点为「AI 分类 / 语义检索额度」，但未定义额度形态：按次数？按库规模上限？按索引条目数？若免费档限制过松则无转化，过紧则伤害 D1 激活率（激活定义本身就要求「完成一次自动分类」）。 | 产品负责人 |
| **Q5** | **首发平台与桌面技术栈？** | macOS 优先还是 macOS/Windows 同发？影响本地 AI 推理方案选型（Apple Silicon 加速 vs 跨平台方案）、PDF 渲染方案与工作量估算，且直接影响 §6 全部估算的可信度。 | 技术负责人 |
| **Q6** | **PDF 文件的物理管理策略默认值？** | 「复制进库目录（可读命名）」保证库自洽但占双倍磁盘；「原地链接」省空间但文件被用户移动后即失联。Persona A 的 1,400 篇混乱库更适合复制，Persona B 的 5,000+ 篇大库更在意磁盘。默认值选哪个？ | 产品负责人 |
| **Q7** | **「离线模式」需要做到多强的可证明性？** | US-5 / D3 要求可向机构证明。是仅提供 UI 状态标识，还是需要提供可导出的网络活动日志、甚至第三方审计报告？后者成本高但可能是机构市场的入场券。 | 产品负责人 |
| **Q8** | **arXiv ↔ 正式版的默认引用版本选哪个？** | REQ-M1-07 要求可切换，但默认值有学术规范含义：默认引正式版更规范，默认引 arXiv 更常见于 CS 领域。是否按学科/用户偏好差异化默认值？ | 产品负责人 |
| **Q9** | **v1 是否需要任何形式的匿名使用统计？** | 「默认零出站请求」是核心承诺，但完全无遥测会导致 D1 激活率、检索成功率等关键指标无法测量。是否接受「默认关闭 + 首启显式询问 + 仅上报聚合事件不含任何文献内容」的方案？这直接决定 §1 全部成功指标能否被观测。 | 产品负责人 |
| **Q10** | **范围超支时，MVP 的第一顺位削减项是什么？** | P0 共约 154d，若排期不足，需要预先约定削减顺序。候选：REQ-M1-04（在线补全）、REQ-M1-05 中的 Zotero 库导入（保留 BibTeX/RIS）、REQ-M2-02 降级为「关键词规则分类」。**建议预先拍板，避免临期慌乱决策。** | 产品负责人 |

### 10.2 数析建议验证的关键假设

| # | 假设 | 为何是假设（而非事实） | 建议验证方式 | 证伪后的动作 |
|---|---|---|---|---|
| **H1** | **「审稿人 + 未发表稿件处理者」是可触达且愿付费的细分人群** | Frontiers 数据证明「>50% 在评审中用 AI」且「禁止上传」的矛盾存在，但**未证明**这些人会因此付费购买工具，也未证明这个人群可被有效触达。 | 定向访谈 ≥20 位近一年有评审经历的学者；投放一个「本地 AI 审稿助手」落地页测意向转化 | 若意向极低，D3「隐私优先定位」需从「首要卖点」降级为「支撑特性」，主打卖点改回效率（G1/G2） |
| **H2** | **免费 → 付费 2%–4% 的转化建模成立** | 该区间是行业类比推导，而非本品实测。赛道最大抑制因素恰恰是「免费开源已够用」，实际转化可能显著低于 2%。 | 阶段二末做定价页 A/B 与付费墙实验，至少 1,000 名活跃用户样本 | 若 < 2%：优先做定价与打包实验（如一次性买断、教育折扣、机构包），而非继续堆功能 |
| **H3** | **本地 AI 分类能在消费级硬件上稳定达到 85%** | 这是整个差异化空白①的技术前提，目前**未经验证**，且是 MVP 的 release gate。 | 立项后 2 周内完成技术可行性验证（spike），用真实混合学科基准集跑通 | 若无法达标：要么降级为「关键词 + 元数据规则分类」并重写差异化叙事，要么调整产品定位，**不可降低门槛上线** |
| **H4** | **用户真的会用「语义检索」，而不只是关键词** | 语义检索是主要付费点之一，但用户长期被训练使用关键词。可能出现「功能存在但无人使用」。 | 阶段二上线后观测：语义模式使用率、语义 vs 关键词的检索成功率差值 | 若使用率 < 10%：付费点须转移至「大库性能 + 端到端加密同步」，语义检索降级为增强特性 |
| **H5** | **「数据可自取」真的能提升转化，而非只是让用户更容易离开** | 研究结论称其为「转化说服点」，但存在反向可能：过强的可迁移性降低锁定，用户白嫖导入能力后回到 Zotero。 | 对比实验：在定价页突出/不突出「数据可自取」，观测转化率差异与后续留存 | 若无正向效果：保留能力（G3 是产品原则，不因转化数据而放弃）但从营销主叙事中降权 |
| **H6** | **Zotero 用户愿意「共存」而非「二选一」** | 「互补层」战略假定用户接受同时运行两个工具。但双工具意味着双份维护成本，用户可能拒绝。 | 访谈 ≥15 位重度 Zotero 用户，实测「导入 Zotero 库并共存两周」的留存与主观反馈 | 若拒绝共存：必须重新评估是走「完全替代」（需补齐引文生态，成本极高）还是收窄到「Zotero 不覆盖的裸 PDF 人群」 |

### 10.3 停车场（好想法，但明确不在当前范围）

记录于此以免反复被提出，也避免其偷偷进入需求池：

- 引文网络图谱可视化（被引/施引关系）
- 与 Obsidian / Logseq 的双向实时同步插件
- 阅读进度与产出统计仪表盘
- 基于阅读历史的论文推荐订阅（arXiv daily）
- 多人批注与评论（依赖 NG-1 群组能力，一并排除）
- 本地 AI 论文问答（chat with PDF）——高需求但属于 NG-9 邻近区域，需先明确边界
- 期刊影响因子 / 引用数等外部指标接入（依赖联网，与 G3 默认离网冲突，需单独设计）
