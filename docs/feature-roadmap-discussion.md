# CiteMap 功能现状与下一步讨论稿

> 更新日期：2026-09-04
> 状态：讨论稿，功能优先级尚未最终确定

## 一、目前已有功能

### 1. 项目与论文管理

- 新建、重命名、删除研究项目
- “未分类”系统项目
- 一篇论文加入多个项目
- 从其他项目批量导入论文
- arXiv 搜索、arXiv ID 入库、批量入库
- 本地 PDF 上传、统一保存
- arXiv PDF 下载
- 论文列表、搜索、详情页
- PDF、笔记、标注状态展示

### 2. PDF 解析与 AI 标注

- 使用 PyMuPDF 提取 PDF 文本和版面信息
- 从 PDF 识别 arXiv ID
- 使用 arXiv metadata 修正标题、摘要、作者、分类、日期
- arXiv API 限流时读取摘要页 metadata 降级处理
- 基于摘要和 PDF 章节节选生成中文 TLDR
- 提取核心贡献、领域、子领域、结构化标签
- 识别作者、机构、研究团队关系
- 支持单篇标注、批量标注、重新标注

### 3. 知识图谱

- 团队 Map：以研究团队为节点，关联论文形成边
- 论文 Map：以论文为节点，共享作者形成边
- 按项目生成图谱
- 节点拖拽、缩放、平移、搜索、详情查看
- 点击论文节点进入论文详情

当前限制：

- 论文 Map 表示共享作者关系，不是真实引用关系
- 没有作者节点、机构节点、标签节点等可切换视图
- 没有时间、领域、标签等图谱筛选
- 笔记中的 `[[wikilink]]` 尚未进入 Map
- 图谱 HTML 导出尚未接入前端

### 4. AI 助手

- 多会话管理和多轮上下文
- SSE 流式回答
- 按项目隔离聊天上下文
- 搜索 arXiv、查询本地论文
- 通过工具入库、标注、下载 PDF
- 查看论文详情、笔记和图谱统计

### 5. Markdown 笔记

- 每篇论文创建 Markdown 笔记模板
- YAML frontmatter
- 笔记文件树
- 编辑、预览、保存、删除
- GFM 表格、任务列表、代码块等渲染
- `[[wikilink]]`
- 按项目显示笔记

当前限制：

- `[[wikilink]]` 目前只作为 Markdown 文本展示，没有生成笔记关系图
- 笔记没有全文搜索
- 笔记与 PDF 页码没有双向定位
- 没有高亮、摘录、批注结构
- 没有 Obsidian 笔记库一键导出或双向同步

### 6. 基础产品体验

- 项目 Dashboard
- CiteMap `Research Workspace` 桌面 UI
- 明暗主题
- 加载、错误、重试状态
- SQLite 本地存储和旧库迁移

## 二、建议接下来做的功能

### P0：项目论文雷达

目标：每天自动发现与各研究项目相关的 arXiv 新论文。

- 每个项目独立开启或关闭雷达
- 每日统一获取一次 arXiv 新论文
- 应用启动时检查漏跑并自动补跑
- 支持手动“立即扫描”
- category、include keywords、exclude keywords
- anchor papers，即项目核心论文
- Top K、最低匹配分数
- 站内未读提醒，不依赖邮件
- 今日推荐、全部、已保存、已忽略
- 显示匹配分数、推荐理由、中文 TLDR
- 一键加入当前项目、可选下载 PDF
- 未保存候选不进入正式论文库

第一版匹配算法：

```text
项目论文 title + abstract
→ embedding
→ 与每日 arXiv 候选计算 cosine similarity
→ 按论文加入时间加权
→ anchor papers 额外加权
→ Top K
```

第二版候选算法：

```text
项目描述 + 关注主题 + anchor papers + 核心贡献
→ project profile
→ 专用 rerank 模型
→ 相关度排序
```

### P1：论文管理基础补全

- 文件夹递归导入、多文件拖拽
- 导入队列、进度、暂停、继续、取消
- 重复论文检测和版本合并
- 手动编辑、删除、归档论文
- 手动标签管理
- BibTeX、RIS、Zotero 导入
- BibTeX、RIS 导出和稳定 citekey

### P1：检索与阅读闭环

- PDF 正文全文搜索
- 标题、摘要、正文、笔记、批注统一检索
- 命中上下文、关键词高亮、跳转 PDF 页码
- 内置 PDF 阅读器
- 高亮、摘录、批注
- 未读、在读、已读、星标、待读队列
- Markdown 批注导出和页码回链

### P1：Map 与笔记增强

Map：

- 增加作者、机构、标签等节点类型
- 支持按年份、领域、标签、作者筛选
- 将笔记 `[[wikilink]]` 解析为关系边
- 从 Map 直接打开论文、笔记、作者或团队详情
- 保存节点位置和用户布局
- 导出图谱图片、HTML 或结构化数据

笔记：

- 笔记标题和正文全文搜索
- 自动补全论文 `[[wikilink]]`
- 反向链接：查看哪些笔记引用了当前论文
- 在论文详情、PDF 阅读器、Map 之间双向跳转
- 从 PDF 高亮或摘录创建带页码的笔记
- 按项目批量导出 Obsidian 可读笔记库
- 将笔记正文纳入 AI 助手和检索范围

### P2：增强能力

- MinerU 可选深度解析
- 本地语义检索
- 单篇 PDF 问答、多篇论文对比
- 基于 OpenAlex、Semantic Scholar 或 Crossref 的真实 citation graph
- Obsidian 笔记库导出或同步
- 全局 Command Palette
- Tauri 桌面应用和 GitHub Actions 构建
- 本地备份、恢复、WebDAV 同步

## 三、当前需要讨论并拍板

1. 雷达第一版只做算法 A，还是同时实现 A/B 切换？
2. embedding 使用本地模型还是 API？
3. 算法 B 使用哪个 rerank 模型，本地 CrossEncoder 还是 API？
4. 雷达默认每天几点运行？是否需要浏览器系统通知？
5. anchor papers 由用户手动选择，还是同时自动选择最近论文？
6. 下一阶段是否只做雷达，暂缓全文搜索、PDF 阅读器、Tauri？
7. MinerU 是否接受上传 PDF 到第三方服务，默认手动还是关闭？
8. Map 下一步优先做真实 citation graph，还是先做笔记 `[[wikilink]]` 关系图？
9. 笔记继续作为论文附属内容，还是允许创建不绑定论文的独立研究笔记？
10. Map 是否需要同时展示论文、作者、团队、机构、标签和笔记，还是保持多个独立视图？

## 四、建议的最近两个迭代

### 迭代 1：雷达 MVP

- 雷达配置、运行记录、候选、匹配数据表
- arXiv 每日抓取和启动补跑
- 算法 A、anchor papers、Top K
- 雷达页面、未读状态、一键入库、忽略

### 迭代 2：雷达质量与论文管理

- 算法 B 或混合评分
- 保存/忽略反馈参与排序
- 推荐效果评测
- 文件夹批量导入、去重
- BibTeX/Zotero 导入导出

### 迭代 3：Map 与笔记闭环

- 笔记全文搜索、wikilink 自动补全、反向链接
- 笔记关系进入 Map
- Map 筛选、节点类型切换、布局保存
- PDF 摘录、页码回链、笔记跳转
- Obsidian 笔记库导出
- 评估并接入真实 citation graph 数据源
